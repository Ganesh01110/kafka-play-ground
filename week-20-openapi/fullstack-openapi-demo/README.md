# 🚀 Full-Stack OpenAPI Demo Project

This project demonstrates a professional, type-safe full-stack workflow using **OpenAPI (OAS 3.0)** as the single source of truth.

It shows how to link a **Node.js/Express backend** and a **React frontend** using an auto-generated contract, eliminating manual API calls and synchronization bugs.

---

## 📁 Project Structure & Links

The three main folders work together like this:

### 1. 🟢 Backend (`/backend`)
*   **Role**: The "Source of Truth".
*   **Key File**: `src/openapi.ts` defines the logical contract (endpoints, types).
*   **What it does**:
    *   Runs the API server (Port 4000).
    *   Validates incoming data using **Zod**.
    *   Generates the `shared/openapi.json` contract file.

### 2. 🟡 Shared (`/shared`)
*   **Role**: The "Bridge".
*   **Key File**: `openapi.json`
*   **What it does**: This is a physical file generated by the backend. The frontend reads this file to understand the API. It ensures both sides speak exactly the same language.

### 3. 🔵 Frontend (`/frontend`)
*   **Role**: The "Consumer".
*   **Key Folder**: `src/client/` (Auto-generated).
*   **What it does**:
    *   Runs the React UI (Port 5173).
    *   **NEVER** writes manual `fetch()` calls.
    *   Uses the auto-generated client to call the backend with 100% type safety.

---

## 🔍 How It Works (Behind the Scenes)

1.  **Contract Definition**: We define the API structure (paths, methods, schemas) in the backend code.
2.  **Generation**: We run a script (`npm run generate-spec`) that converts our code definition into a standard `openapi.json` file.
3.  **Client Creation**: The frontend runs a generator tool (`npm run generate-client`) that reads that JSON file and spits out a TypeScript SDK (`src/client/`).
4.  **Consumption**: The React app imports functions from that SDK. If the backend changes a type, the frontend build **fails immediately**, preventing bugs before they happen.

## 🎮 How to Run & Explore

### Step 1: Start the Backend
```bash
cd backend
npm install
npm run dev
```
*   Server starts at `http://localhost:4000`.

### Step 2: Access OpenAPI Spec in Browser
Once the backend is running, you can explore the spec in two ways:

1.  **Interactive UI (Swagger UI)**:  
    👉 **[http://localhost:4000/api-docs](http://localhost:4000/api-docs)**  
    *   *What is this?* A visual website where you can test your API endpoints manually. Try the `GET /api/tasks` button!

2.  **Raw Spec (JSON)**:  
    👉 **[http://localhost:4000/api/openapi.json](http://localhost:4000/api/openapi.json)**  
    *   *What is this?* The raw data that tools use to generate code.

### Step 3: Start the Frontend
```bash
cd frontend
npm install
npm run dev
```
*   App starts at `http://localhost:5173`.
*   Open the browser console to see network requests being made by the generated client.

## 🛠️ Modifying the API (The Workflow)

Want to add a new field or endpoint? Follow this "Cycle of Safety":

1.  **Modify Backend**: Update `backend/src/openapi.ts` and `schemas.ts` with the new field.
2.  **Regenerate Spec**: Run `npm run generate-spec` in the backend folder.
3.  **Regenerate Client**: Run `npm run generate-client` in the frontend folder.
4.  **Update Frontend**: Now your React code has access to the new field with full autocomplete!

## 🔧 Troubleshooting

*   **Frontend Build Error?**
    If you see `Cannot find type definition file for 'node'`, run:
    ```bash
    cd frontend
    npm install -D @types/node
    ```

*   **Client Generation Failed?**
    Make sure the backend has generated the `shared/openapi.json` file first!
